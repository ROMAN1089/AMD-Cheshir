# SnapSell — подготовьте один раз, продавайте на ваших площадках

SnapSell превращает видео с инвентаризацией в проверенные объявления для перепродажи, исследует рыночные цены и готовит материалы для **eBay, Facebook Marketplace и Craigslist**. Покупатели и платежи остаются на самих торговых площадках.

## Текущий рабочий процесс

1. **Инвентаризация:** загрузите видео с реальными товарами с англоязычным голосовым описанием или добавьте товар вручную. Компьютерное зрение на базе моделей AMD создает черновые карточки по 26 категориям и разделу "Другое". Локальный Whisper транскрибирует английскую речь.
2. **Проверка и исследование:** подтвердите зафиксированные факты. Неизвестные модели можно исследовать по фотографии. Модели-кандидаты с подтвержденными источниками остаются неподтвержденными до тех пор, пока продавец не сравнит их. Числовые ценовые рекомендации требуют достаточного количества совпадающих рыночных свидетельств.
3. **Каналы продаж:** выберите товар и торговую площадку. SnapSell сформирует подходящий заголовок, описание, доступную запрашиваемую цену и реальную фотографию. Скопируйте текст или скачайте ZIP-комплект объявления. Подкрепленная рыночной медианой рекомендация подставляется автоматически, если продавец еще не установил цену; при нехватке данных поле цены остается пустым.
4. **Публикация вовне:** опубликуйте настроенное предложение на eBay через коннектор или откройте форму на торговой площадке и разместите объявление вручную в аккаунте продавца. Зафиксируйте фактический URL опубликованного товара в SnapSell. Скачивание комплекта никогда не помечает товар как опубликованный.
5. **Стол ответов покупателям:** вставьте вопрос покупателя с торговой площадки, проверьте предложенный фактологический ответ и скопируйте его обратно. Ответы формируются как черновики; входящие сообщения торговых площадок не синхронизируются, и SnapSell не отправляет сообщения напрямую.
6. **Сделки:** добавьте интервалы доступности для самовывоза и места встреч, забронируйте проверенный товар за конкретным покупателем, зафиксируйте согласие покупателя, переносите/отменяйте встречи и подтверждайте факт самовывоза или неявку. Доступны приватные напоминания внутри приложения и ручной экспорт в календарь. См. [организация самовывоза](docs/DEALS.ru.md).
7. **Результаты:** зафиксируйте завершенную внешнюю продажу с указанием фактической комиссии площадки и стоимости приобретения товара. Вклад в прибыль рассчитывается как цена продажи за вычетом зафиксированной комиссии и стоимости закупки. Другие зафиксированные копии товара помечаются для удаления. Связанные копии на eBay отзываются через API; копии на других площадках продавец удаляет вручную и подтверждает удаление в системе.

## Статус интеграций

| Направление | Работает сейчас | Прямая публикация |
|---|---|---|
| eBay | ZIP-комплект, авторизация продавца через OAuth, публикация/обновление/статус/отзыв через Inventory API, привязка существующих SKU | По умолчанию Sandbox; требуются ключи разработчика и авторизация продавца |
| Facebook Marketplace | ZIP-комплект, копируемый текст/фото, отслеживание ссылок и черновики ответов | Ручное размещение в аккаунте продавца |
| Craigslist | ZIP-комплект, копируемый текст/фото, отслеживание ссылок и черновики ответов | Ручное размещение в выбранном продавцом городе |

Коннектор eBay реализует штучные объявления `FIXED_PRICE` на `EBAY_US`. Настройте его с помощью [бесплатного руководства по настройке Sandbox](docs/EBAY_SETUP.ru.md). Публикация в боевом режиме (Live) требует ключей разработчика и авторизации продавца. Для публикации на eBay требуются OAuth-авторизация продавца, корректная конечная категория и параметры (aspects), поддерживаемое состояние товара, публичные URL фотографий, местоположение инвентаря и идентификаторы бизнес-политик. Экспортируемый JSON указывает недостающие поля; он **не** является готовым запросом для боевой публикации. [Официальные требования к публикации eBay](https://developer.ebay.com/api-docs/sell/static/inventory/publishing-offers.html).

Массовое размещение на Craigslist регулируется ограничениями доступа и предназначено для подтвержденных аккаунтов с большими объемами в определенных платных категориях; данный прототип использует ручное размещение. [Официальный интерфейс массовой публикации](https://www.craigslist.org/about/bulk_posting_interface). Для Facebook используется стандартный интерфейс продавца для ручного переноса. [Справка по продажам на Facebook](https://www.facebook.com/help/550954179351183/).

Статусы ручных объявлений и финансовое завершение сделок **сообщаются продавцом**. Связанные предложения eBay опрашиваются через API каждые две минуты во время работы `app.py`. Проданный на eBay товар блокирует повторное выставление, но не фальсифицирует данные об оплате или комиссиях. Локальные изменения помечаются для синхронизации; используйте «Update on eBay» после их проверки. Связанные копии eBay, поставленные в очередь на удаление, отзываются через API; на других платформах требуется ручное удаление. Скачивание или копирование материалов не приводит к автоматической внешней публикации, оплате или отправке сообщений.

## Запуск в один клик на Windows

После начальной настройки дважды кликните по файлу **Start SnapSell.cmd** в папке проекта. Он проверяет установленные зависимости, запускает локальный API и веб-интерфейс, после чего открывает <http://127.0.0.1:3000>. При первом запуске выполняется сборка production-версии сайта; последующие запуски переиспользуют её до тех пор, пока исходные файлы фронтенда не изменятся. Фоновые процессы Python и Node работают без открытия отдельных окон консоли. Лаунчер не скачивает пакеты и не активирует платные сервисы.

Держите окно лаунчера открытым и нажмите **Ctrl+C** в нем, чтобы остановить запущенные им серверы. Если SnapSell уже был запущен ранее, лаунчер подключится к нему и не затронет существующие процессы. Логи работы сохраняются в `private/backend.log`, `private/frontend.log` и `private/build.log`.

Для проверки готовности окружения без запуска серверов:

```powershell
& ".\Start SnapSell.cmd" --check
```

Node.js определяется из переменной `PATH`, установленной среды выполнения Codex или стандартной папки Program Files на Windows. Переменная окружения `SNAPSELL_NODE` позволяет указать альтернативный путь к `node.exe`. Стандартные порты 3000/5000 соответствуют настроенному Google OAuth callback. Начальная установка зависимостей описана ниже; стандартный запуск в двух терминалах разработки также доступен.

Подробный отчет обо всех изменениях и текущих ограничениях см. в [отчете о сессионных изменениях](docs/SESSION_CHANGES.ru.md).

## Локальная установка и настройка

Протестировано с Python 3.11 и Node.js 22+; требуется `pnpm`.

```powershell
Copy-Item .env.example .env
# Укажите AMD_API_KEY и при необходимости SELLER_PASSWORD в .env
python -m venv .venv
.venv/Scripts/python -m pip install -r snapsell-backend/requirements.txt
pnpm --dir snapsell-frontend install --frozen-lockfile
.venv/Scripts/python snapsell-backend/speech.py
```

Скрипт настройки распознавания речи скачивает зафиксированную модель с проверенным хешем (~75 МБ), кешируемую в `data/models/tiny.en`. Транскрибация аудио выполняется локально на CPU. Модели AMD выполняют распознавание по фото (vision), поиск наименования товара, планирование исследований, классификацию намерений покупателей и сведение доказательств. Доступные модели определяются во время выполнения; API-ключ хранится исключительно на сервере.

Запуск в двух терминалах из корня репозитория:

```powershell
.venv/Scripts/python snapsell-backend/app.py
```

```powershell
pnpm --dir snapsell-frontend dev
```

Откройте [SnapSell](http://127.0.0.1:3000). Параметр `LOCAL_ACCESS=true` включает быстрый локальный вход с паролем `snapsell-local`. Для развертывания в сети установите `LOCAL_ACCESS=false`, задайте надежный `SELLER_PASSWORD`, используйте HTTPS и `COOKIE_SECURE=true`. Сохраняйте директорию `data/` и запускайте один процесс бэкенда; прерванные задачи можно перезапускать.

## Принятие ценовых решений

Система стартует без искусственно сгенерированного инвентаря, фиктивных предложений или активности покупателей. Цены формируются на основе извлекаемых свидетельств реальных продавцов, а не придуманных чисел. Веб-оценка требует как минимум трех различных совпадающих страниц товара не менее чем от двух продавцов. Ссылки с вариантами или трекингом не создают независимых наблюдений. Сбалансированные по продавцам веса актуальности, проверка выбросов по MAD и взвешенные квартили формируют ценовые ориентиры с учетом себестоимости, оценочной комиссии и минимума продавца. Запрашиваемые цены не являются гарантией завершенных продаж.

Без достаточного объема реальных исходов за последние 7 дней прогнозы вероятности продажи и ожидаемой доходности остаются недоступными. См. [исследование цен](docs/PRICE_RESEARCH.md) и [валидацию](docs/VALIDATION.md).

## Проверки и происхождение кода

```powershell
.venv/Scripts/python -m pip install pytest
.venv/Scripts/python -m pytest snapsell-backend/tests -q
pnpm --dir snapsell-frontend typecheck
pnpm --dir snapsell-frontend build
```

Тесты используют изолированную базу данных. Исходный код базируется на репозитории [CollinQ/sbhacks2025](https://github.com/CollinQ/sbhacks2025), сохраненном с лицензией MIT в папке `upstream/`. База данных SQLite обеспечивает надежную работу для одного продавца. Сервис AMD Token Factory является экспериментальной средой разработки; для промышленной эксплуатации требуется поддерживаемый эндпоинт инференса.

Ранний концепт CHESHIRE сохранен в файлах [docs/CHESHIRE_CONCEPT.md](docs/CHESHIRE_CONCEPT.md) (на английском) и [docs/CHESHIRE_CONCEPT.ru.md](docs/CHESHIRE_CONCEPT.ru.md) (на русском).

Исследование цен поддерживает переключение регионов US/USD, Казахстан/KZT, Япония/JPY и Китай/CNY, раздельные ссылки на похожие товары, сравнение доставки на основе источников и опциональное ежедневное автообновление. Зарубежные оценки никогда не перезаписывают учет инвентаря в USD. Опциональный поиск через eBay Browse и сбор 7-дневных исходов описаны в [документации по исследованию цен](docs/PRICE_RESEARCH.md).

Интеграция с Google Calendar настраивается на панели сделок (Deals): проверка доступности в основном календаре, автоматическое создание и обновление событий самовывоза, повторные попытки при сбоях и всплывающие напоминания. Настройте клиент Web OAuth и авторизуйте учетную запись согласно [руководству по Google Calendar](docs/GOOGLE_CALENDAR.ru.md). Внешние изменения в календаре не перезаписывают локальные встречи.
